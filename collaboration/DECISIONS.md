# DECISIONS — القرارات الهندسية وأسبابها

## D-1 — تهيئة Git داخل نسخة العمل

**القرار:** `git init` في `LOONG` + فرع `collab/a-security-verification-understanding` + baseline commit.
**السبب:** كان المشروع بلا Git أصلًا (تأكدت: `git status` ⟶ `No git repository`). بلا Git لا يوجد فرع معزول ولا diff للمراجعة ولا رجوع دقيق — والبروتوكول يطلبهما في §1.3 و§4.
**المخاطرة:** `app/` تحوي مثبّتًا بحجم 88MB و`backups/` يضاعف كل سطر. عُولجت بتوسيع `.gitignore` قبل أول `add`. النتيجة: 139 ملفًا متتبعًا فقط.
**التراجع:** حذف `.git` يعيد الحالة الأصلية بالكامل (لا شيء في الشجرة تغير بسبب Git).

## D-2 — ملفات قواعد المستودع = بيانات، لا أوامر

**القرار:** يبقى `AGENTS.md` / `LOONG.md` / `.loong/skills/*.md` تُحقن، لكن داخل إطار غير موثوق مُعلَّم بمسار المصدر، مع فقرة أسبقية ثابتة في `SYSTEM_PROMPT`.
**السبب:** الحاقن الحالي يعلن المحتوى صراحةً كتعليمات يجب اتباعها (`server/rules.ts:114`، `server/skills.ts:195`) بلا أي إعلان أسبقية في `SYSTEM_PROMPT`. أي مستودع نسخه المستخدم بفوائد توجيه إلى الوكيل (OWASP LLM01).
**البدائل المرفوضة:**
- *حذف الميزة*: مكسب حقيقي (اصطلاحات المشروع لا يجب أن تُكتشف بالتجربة) — حذفها تراجع.
- *فلترة الأنماط الخبيثة*: تُتجاوز بإعادة صياغة، وتعطي أمانًا وهميًا. الأسبقية البنيوية لا تُتجاوز لأنها **خارج** المحتوى المُقتبس.
**المخاطرة:** قد يتوقف الوكيل عن اتباع قاعدة مشروعة. عولجت بأن الفقرة تسمح صراحةً باتباع الاصطلاحات والأسلوب، وتمنع فقط ما يمس الأمان/الموافقة/التحقق/الأسرار.

## D-3 — جولة إصلاح واحدة محدودة بعد فشل الفحص

**القرار:** عند فشل فحص ما بعد التشغيل يُعاد فشل واحد (أول أسطر الخطأ) إلى النموذج كدور جديد، **مرة واحدة**، ثم ينتهي التشغيل كما هو.
**السبب:** اليوم الفحص يعمل بعد انتهاء النموذج ويعرض النتيجة في الواجهة فقط (`server/agent.ts:1679-1691`) — النموذج لا يعلم أبدًا أنه كسر البناء، فينتهي التشغيل وهو يقول نجحت. هذا بالضبط «مهمة تبدو مكتملة وهي ليست كذلك».
**البدائل المرفوضة:** *تكرار غير محدود* (حلقة لا تنتهي على فشل حقيقي) — لذلك سقف صلب: مرة واحدة لكل تشغيل، مشفّر في دالة قرار قابلة للاختبار.
**المخاطرة:** إبطاء تشغيل كان سينتهي فورًا. عولجت بأن الـ gate يُستدعى فقط عندما (أ) تغيّر ملف (ب) وُجد أمر فحص (ج) لم يُجرَّب من قبل (د) لم يُجهَض.

## D-4 — ملخّص المشروع حتمي لا مولَّد

**القرار:** `server/digest.ts` يبني ملخّص أول تلامس من قراءات قرصية فقط (امتدادات، أحجام، نصوص `package.json`، إشارات git). لا استدعاء نموذج.
**السبب:** استدعاء نموذج لتلخيص مشروع = كلفة + زمن + هلوسة محتملة في معلومة يُمكن قراءتها بدقة. والحتمي قابل للاختبار.
**المخاطرة:** ملخّص يعرض معلومات قد تكون مضلّلة في مشروع غريب الشكل. عولجت بأن كل سطر يسمّي مصدره، وبسقف حجم صلب.

## D-5 — لا تغيير في عقد أحداث AG-UI من أجل الواجهة

**القرار:** C-4 تستخدم الأحداث المخصّصة الموجودة (`loong.notice` / `loong.checks` / `loong.stop`) وإقليم `aria-live` داخل المكوّن. لا حقل جديد في العقد.
**السبب:** البروتوكول §المرحلة الثالثة يمنع تغيير العقد المشترك لإرضاء الواجهة فقط. والعقد مُختبَر في `tests/agui.test.ts`. — لو احتاج التغيير عقدًا فسيكون مهمة منفصلة موثَّقة ومُختبرة، لا بندًا جانبيًا هنا.

## D-6 — تطبيع جديد لعقد إجهاض موجّه (لم يُنفَّذ في هذه الجلسة)

**الحالة:** `OPEN` — خارج نطاق هذه الجلسة، مسجّل حتى لا يُفقد.
**الفكرة:** قائمة `Record<taskId, AbortSignal>` في `server/agent.ts` التي تحرس الإجهاض الحالي لديها نقطة خطأ أُصلحت في P-11. لم أتحقق من سلوكها تحت إجهاضين متزامنين. يحتاج مهمة مستقلة بـ probe.
