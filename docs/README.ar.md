# لوونج — دليل البداية والبناء على Windows

لوونج أداة برمجة تعمل محليًا على جهازك. تستطيع قراءة المشروع، وتعديل الملفات، وتشغيل الأوامر، وعرض التغييرات والفحوص. الإصدار الحالي **3.0 تجريبي**؛ تختلف جودة التنفيذ حسب الموديل والمزوّد، ولا توجد نتيجة تقييم حي معلنة لمجرد نجاح الاختبارات المحلية.

[الصفحة الرئيسية](../README.md) · [التوثيق](README.md) · [الإصدارات](https://github.com/alros2yhmh-commits/loong/releases)

## تنزيل نسخة جاهزة

إذا كان الإصدار يحتوي ملف `Loong-<version>-Setup-x64.exe`، نزّله من صفحة Releases وقارن بصمته مع `SHA256SUMS.txt`، ثم شغّله واتبع خطوات التثبيت. لا تحتاج Node.js لتشغيل النسخة المثبّتة. قد يظهر تحذير SmartScreen للنسخ التجريبية غير الموقّعة؛ البصمة تتحقق من سلامة التنزيل ولا تثبت هوية الناشر.

إن لم يوجد ملف Setup منشور، استخدم البناء من السورس أو نزّل artifact من تشغيل ناجح في GitHub Actions. وجود workflow لا يعني أن الـSetup بُني بنجاح بالفعل.

## تنزيل السورس وبناء Setup بنفسك

المطلوب: Windows 10 أو 11 بنواة x64، وGit، وNode.js **24 LTS**. عند الحاجة لبناء مكتبة الطرفية الأصلية، ثبّت Visual Studio 2022 Build Tools مع **Desktop development with C++** وPython 3، ثم افتح نافذة PowerShell جديدة.

```powershell
git clone https://github.com/alros2yhmh-commits/loong.git
cd loong
node --version
npm ci
npm test
npm run build:exe
```

ينبغي أن يعرض أمر Node إصدارًا يبدأ بـ`v24`. بعد نجاح البناء ستجد، للإصدار الحالي:

```text
app\Loong-3.0.0-beta.1-Setup-x64.exe
```

شغّل الملف، واختر مكان التثبيت، ثم افتح **Loong** من سطح المكتب أو قائمة Start. ويمكن اختبار النسخة غير المثبّتة من `app\win-unpacked\Loong.exe`. اسم ملف الـSetup يتبع رقم الإصدار في `package.json`.

لجلب التحديثات لاحقًا من مستودع محلي نظيف:

```powershell
git pull --ff-only
npm ci
npm run build:exe
```

احتفظ بتعديلاتك الخاصة في commit أو نسخة احتياطية قبل التحديث.

## أول مهمة

1. افتح مجلد مشروعك من الواجهة.
2. افتح **Settings → API keys** واختر المزوّد وضع المفتاح داخل التطبيق؛ لا تنشره في issue أو commit. Ollama يحتاج خدمة محلية وموديلًا يدعم الأدوات بدل مفتاح سحابي.
3. اختر موديلًا من القائمة. **Fixed** يثبّت الاختيار؛ **Auto** يسمح بسياسة البدائل المتوافقة. النماذج المجانية لها حدود ضغط واستخدام، ولا تتحول تلقائيًا إلى مدفوعة ضمن مسار المجاني.
4. اختر **Agent** للتنفيذ، أو **Plan** لخطة وقراءة فقط، أو **Ask** للإجابة دون أدوات. الصلاحيات منفصلة: **Ask first** يطلب موافقات، و**Full trust** يسمح بالعمليات المدعومة داخل نطاق المشروع.
5. اكتب المطلوب بوضوح، ثم تابع Changes وChecks وTerminal. راجع التغييرات ونتائج الفحوص قبل دمجها أو نشرها.

النتيجة الجزئية أو المحجوبة أو الفاشلة ليست مهمة مكتملة. انقطاع الاتصال أيضًا ليس دليل نجاح؛ تابع حالة المهمة وسبب التوقف.

## تشغيل السورس أثناء التطوير

```powershell
$env:LOONG_WORKSPACE = (Get-Location).Path
npm run dev
```

افتح عنوان Vite الذي يظهر في الطرفية. لاختيار المجلد من نافذة Windows الأصلية، شغّل واجهة Electron:

```powershell
npm run build
npm run desktop
```

## بيانات التطبيق وحدود الأمان

النسخة المثبّتة تحفظ بيانات الإيجنت داخل مجلد بيانات تطبيق Loong الخاص بالمستخدم، ونسخة التطوير تستخدم `~/.loong` ما لم تحدد `LOONG_DATA_DIR`. عند توفر مخزن مفاتيح النظام، تُشفّر مفاتيح المزوّد محليًا باستخدام مفتاح تثبيت محمي بـElectron safeStorage. يعرض قسم API keys وضع الحماية الفعلي؛ نسخة التطوير أو Linux دون keyring مناسب تستخدم تخزينًا محليًا محدود الأذونات وتوضح أنه غير مشفر. لا يُستبدل مخزن مشفر قديم إذا تعذر فتحه. احمِ مجلد البيانات والنسخ الاحتياطية منه.

الأوامر تعمل بصلاحيات حسابك. الحواجز البرمجية والموافقات ليست عزلًا كاملًا لنظام التشغيل؛ استخدم VM أو container أو حساب تطوير منفصل للمشاريع غير الموثوقة. Full trust لا يعني تعطيل حدود الأمان.
